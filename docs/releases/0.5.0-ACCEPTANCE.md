passes only when it is backed by the named automated or packaged verification;
sample data and simulated runtime events do not count.

## 4. Windows capabilities

The frozen registry contains 19 real capability ids:

- workspace text create/read/append, list/search/copy/move, folder create, and
  critical delete;
- approved application launch;
- separate clipboard read and write;
- notification;
- visible, audited, grantable screen capture inside the artifact root;
- privacy-safe system, storage, and bounded process reports;
- validated HTTP(S) URL opening;
- bounded VS Code project launch inside the approved workspace.

Acceptance requires adapter, validator, risk/scope, and E2E coverage; all native
process launches use `shell: false`. There is no arbitrary executable, argv,
environment, working directory, shell, PowerShell, script host, or broad wildcard
grant surface.

## 8. Accepted limitations

- The deterministic phrase interpreter is intentionally narrow. Provider-backed
  planners are the next layer and must emit the existing plan contract.
- Agent Profile/workflow authoring is not exposed as a full editor yet; the real
  validated models and starter systems prove the runtime first.
- Execution is sequential in 0.5; concurrency requires a separate scheduling and
  resource-contention design.
- Capability adapters are Windows-only. Shared contracts are platform-neutral.
- The inherited update feed remains disabled until a real Morpheus endpoint exists.
- Local Authenticode signing may be unavailable; CI SignPath status is reported
  truthfully and never simulated.
- macOS packaging still needs a Morpheus `.icns` generated on macOS before it is
  a credible distribution artifact.
