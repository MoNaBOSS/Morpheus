# Morpheus 1.1.0 Production Companion candidate

## Target

Turn the verified 1.0.5 execution foundation into a coherent Windows operator
experience without weakening Main-owned authority or representing an unsigned,
untested build as a public commercial release.

## Candidate acceptance

- First-run activation introduces Morpheus, asks the user's preferred name and
  offers an explicit tray/background choice.
- Command Center is mission-first at 1280x800 and does not resemble a chat feed.
- Global shortcut, tray and wake events summon one compact Presence surface.
- Push-to-talk automatically detects end of speech and never transcribes a
  silent timeout.
- Listening, transcription, planning, execution, approval, completion and
  speaking visuals come from real runtime state.
- Voice result playback opens only a bounded follow-up turn and remains
  interruptible.
- Neural and Windows fallback speech are distinguished; provider failure is
  visible and actionable.
- Provider planning remains bounded and reports real stage latency and usage
  metadata without persisting prompts or speech.
- Existing OpenClaw Chat, gateway, capabilities, grants, artifacts, Missions,
  workflows, schedules and Activity continue to function.
- Typecheck, lint, focused unit/Electron tests, full Morpheus E2E, Windows
  packaging and a normal packaged smoke test pass.

## Public commercial gates

This candidate is not publicly releasable until the independent requirements
in `PUBLIC-RELEASE-GATES.md` pass. In particular: a Morpheus publisher
certificate, real provider and microphone trials, clean-machine install and
upgrade trials, owned update/support endpoints, privacy/legal review and
provider-side cost reconciliation cannot be replaced by local test fixtures.

## Provider efficiency boundary

Morpheus planning requests produce compact typed JSON plans, so the direct
planner reserves at most 2,048 output tokens for ordinary objectives and 4,096
for website objectives. A planner instance may issue at most four requests and
reserve at most 12,288 output tokens. Completed deterministic execution skips an
unnecessary provider review. Usage is audit-metered when the provider reports
token counts. These bounds reduce accidental cost; they are not a currency
guarantee, and OpenClaw Chat has its own provider usage lifecycle.

  passing evidence after the three activation-visibility cases were re-run 9/9
  against the final rebuilt output.
- Full units: 2,728 passed and 2 skipped. The inherited OpenAI-image local HTTP
  fixture timed out in the full run and alone; no product assertion was relaxed.
- Harness task validation/dry-run and communication replay/comparison pass.
- Visual review covers first-run activation, ready state, Command Center,
  Presence and returning greeting at 1280x800 and 1920x1080, plus the 800x800
  fallback. The full-screen greeting owns its speech presentation without a
  second floating HUD; live microphone/error states remain visible.
- A fresh isolated normal packaged launch passed setup, activation, live Gateway
  readiness, a real system report, Command Center and Chat. It produced no page
