# Companion interaction boundaries

See docs/roadmap/COMPANION-EXPERIENCE-MILESTONES.md for the approved campaign.
Voice dialogue state is ephemeral input routing, never execution authority.
The existing typed host facade, Main settings, provider service, audit and
Objective Core remain authoritative. Audio energy is a local visual signal,
not evidence of recognition or task success. Background listening remains opt-in.

Regression checks must cover bare wake, exact token boundaries, Unicode offsets,
follow-up expiry, stale asynchronous responses, mute/cancel, settings changes,
audio-resource disposal, reduced motion and truthful preview outcomes.

The MP3 Electron fixture generates silent frames and exercises real decoding and
chunk delivery before generation finishes. It is not a real neural provider test.
The local wake helper fixture tests protocol and ownership, not real-world wake
accuracy. The native device probe on 2026-09-14 loaded English recognition but
could not open the default audio device. Preserve this distinction in handoffs.

The 1.0.5 motion check covers repeated invocation, live system-report execution,
arrival at three viewport sizes, focus and reduced motion. Its speech/fallback
presentation fixtures do not prove microphone or provider readiness. Greeting can
own speech presentation, but never conceal an active input or its error recovery.

The 1.1.0 Presence contract adds automatic end-of-speech for explicit capture,
bounded post-result follow-up, a natural installed-voice selector for truthful
Windows fallback and a mission-first Command Center. Follow-up convenience does
not authorize a capability; Objective Core and plan-level trust remain the only
execution path.
